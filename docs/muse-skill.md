# Muse 美学鉴赏 skill — 设计沉淀

> 状态：**稳定（v1.2.0）**，已进入实测迭代期。本文是 skill 的权威设计说明与决策记录，后续改动应同步更新此处。

## 一、这是什么

Muse 是一个**通用美学鉴赏 skill**：给定一张图片（UI 截图 / 摄影 / 海报 / 画作），按审美维度打分并给出**带原因与美学效果描述**的可执行改进建议。

- 位置：`~/.agents/skills/muse/`（用户级，跨项目可用）
- 前端名：`muse`，斜杠调用 `/muse <图片>`
- 触发词：美学鉴赏、美不美、好看吗、评鉴这张图、aesthetics review

## 二、立项目标（为什么做）

用户是 Agent 开发工程师，需要一个 Agent 协助判断"这个东西到底美不美"，服务两个真实场景：
1. **前端项目**——页面美不美、哪里不美、怎么改。
2. **短剧项目**——镜头/画面美不美（当前影视层尚未建，后续）。

判断须**可溯源到知识库**，而非模型自由发挥（"不自嗨"是质量底线）。

## 三、总体架构

```
图片输入 ─→ ① 定类型/风格 + 定场景画像（scenarios.md 路由）
            ② 加载维度 references（6 维 + UI 额外 Material + dynamic）
            ③ 逐维度打分（1-10，按场景调权重）
            ④ 总评 + ⑤ 可执行改进（含动态/自适应建议；必给原因+描述美学变化）
```

核心原则（v1.3.0 起）：
- **通用美学 = 交叉验证，不是裁决**。通用美学（构图/意境/色彩）管感受气质；前端 UI 的权威是**具体设计体系**（Material / HIG），管规范与可执行。两者交叉验证，冲突时尊重设计意图。
- **先定场景画像再评审**。从截图自动判定场景（写作工具/落地页/仪表盘/电商/作品集/内容/工具 App/非 UI 图像），按画像调权重与建议方向。
- **动态/自适应是建议方向**。Material 动态配色/自适应明暗是"该往哪走"的参考，不是硬性必改；有强品牌色时说明用 baseline/品牌 seed 方案。
- **改动必须给原因 + 描述美学变化**，禁止"通用美学/更高级"这类空话。

## 五、Skill 结构与 references

`~/.agents/skills/muse/`
```
SKILL.md            主指令：工作流 + 评审准则 + 输出模板
references/
  color.md          色彩（含 WCAG ≥4.5:1 硬阈值）
  composition.md    构图（含"功能型界面豁免"）
  hierarchy.md      视觉层级（含与构图的分界）
  space.md          留白/空间
  typography.md     排版（含行长 45-75 字符经验值）
  balance.md        比例/平衡/统一
  domains.md        领域加权 / 风格相对性 / 维度交互
  material.md        Material 3 体系（UI 评审尺子，交叉验证用）
  scenarios.md       场景画像路由（8 场景：判定信号/维度权重/锚点/动态建议）
  dynamic.md         动态/自适应层（Material 动态配色、明暗、responsive）
```

**来源三档**：每篇 references 末尾"依据与出处"标注——
- **语料支撑**：知识库原文（含官方规范，如 WCAG、Material、SEP）
- **精编卡**：手工提炼（方向与语料一致，措辞加工过）
- **经验值**：设计惯例，未经验证，引用须注明

## 六、历次修正决策记录

| 版本 | 修正 | 原因 |
|---|---|---|
| v1.0 | 6 维度 + 打分 | 首版通用骨架 |
| v1.1 | 依据与出处三档 + 锚定准则 | 审计发现内容约三成是"模型自嗨"，要求可溯源 |
| v1.1 | WCAG 对比度硬阈值 + 行长 | 补可量化硬标尺，根治"随口说对比不足" |
| v1.1 | domains.md（领域加权/风格相对性/维度交互） | 批评指出：无 domain 路由、维度孤立、风格一刀切 |
| v1.1 | 排版换英文源 | 中文《排版》是空壳小作品 |
| v1.2 | **通用美学=交叉验证** + **改动必给原因&描述美学变化** | 用户强反馈：用通用美学"摁死"前端设计是错的；前端权威是 Material/HIG |
| v1.2 | Material 体系锚定 + 图片通道兜底 | UI 评审打一手地基；Read 读图失败时用 CDN→analyze_image |
| v1.3 | **场景画像路由 + 动态/自适应建议** | 用户推进"智能审美"：看截图自动判定场景（scenarios.md 8 画像），给动态建议（dynamic.md，Material 动态配色/明暗自适应）；写作工具画像引用中国美学（意境/气韵/留白） |

**关键教训**（应持续遵守）：
1. 判断必须可溯源，不编造（图看不到就宁可拒绝）。
2. 通用美学是交叉验证的一维，不是裁决；尊重设计意图。
3. 间距差异常是**有意的优先级表达**，不是"不一致"。
4. 可访问性硬标准（WCAG）与审美冲突时，讲清意图、给不破坏美感的折中。
5. 视觉工具（analyze_image）可能幻觉——多张图矛盾时用本地像素事实（如平均色）仲裁。

## 八、已知边界 / 限制

- **视觉通道不稳定**：当前模型 Read 读图常返回"Unsupported Image"，须走 CDN→analyze_image 兜底，且该工具可能幻觉。
- **动效维度缺失**：muse 的 6 维度都是静态的，对文字类/动效产品是缺口。
- **影视层未建**：短剧场景（景别/运镜/打光/调色/镜头语言）尚无数据。
- **像素值置信度**：绝对数值（字号/间距/色值）依赖视觉工具报告，评分以相对层级为准。
