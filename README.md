# Muse — 美学鉴赏 Agent

> 📄 Skill 设计沉淀见 [`docs/muse-skill.md`](docs/muse-skill.md)（架构、决策记录、实测、路线图）。

## 立项目的（为什么做这个）

我是一个 Agent 开发工程师。在做前端的路上，我发现自己缺一样东西：**对"什么是美"的清晰认知**。它直接影响两件我正在做的事——

1. **前端项目**：需要一个好的美学呈现，页面到底美不美、哪里不美、怎么改。
2. **短剧项目**：画面、镜头需要美学学习，一个镜头/一帧画面到底好不好看、为什么。

所以我需要**一个 Agent** 来协助我，帮我看清一件事：**这个东西到底美不美**。

## 为什么先做数据面

要鉴赏美，得先知道什么是美。但"什么是美"没有标准答案——它是跨越哲学、艺术史、设计原理的问题。所以本项目遵循这个次序：

```
① 数据面  →  采集、清洗原始素材（审美原理、设计、影视、艺术史语料）
② 理论面  →  从数据面提炼出可应用的审美理论与检查框架
③ Agent   →  基于理论面，构建"看作品 → 按原理审 → 给可执行意见"的鉴赏 Agent
```

先建数据面，是因为它是后面所有判断的地基——地基不稳，Agent 的"审美"就是空中楼阁。

## 目标形态（后期）

原理驱动的美学质检 Agent：多模态模型当"眼睛"，结构化审美原理当"框架"，能对
**前端页面 / 短剧镜头**给出可落地的审美评价与修改意见。

## 数据面结构（规划）

```
data/
  principles/   通用审美原理（色彩理论、排版、构图、留白、层级…）
  ui/           前端 UI 美学（间距系统、字号层级、设计语言…）
  cinema/       短剧/影视美学（构图、景别、运镜、打光、调色、镜头语言…）
  foundation/   艺术史 + 经典美学理论（原理溯源）
```

> 数据面以应用层（UI + 影视美学）为重，艺术史/经典理论作溯源支撑。

## 采集脚本

- `scripts/fetch_wikipedia.py --layer principles|ui|foundation`：维基百科（中文优先、缺失/太薄回退英文、中文标题搜索别名）。
- `scripts/fetch_sep.py`：抓斯坦福哲学百科（SEP）美学理论条目到 `data/_raw/foundation/theory/`。

## 后续路线

- **补原理层语料**：对比、平衡、节奏、纹理、动态等主题。
- **补应用层语料**：影视层（景别、运镜、打光、调色、镜头语言）——目前只有 UI 层。
- **理论面**：从数据面提炼结构化的审美理论框架，构建 references 扩展（含中西美学对照）。
- **自动化蒸馏**：语料规模达 50+ 条目后，构建从 `data/` 蒸馏生成 references 的脚本（理论面构建器）。现在手工维护，避免过早自动化。
